CIDR to IP range

Paste a block such as 198.51.100.0/24 into the field above and the range is already in the answer: First usable host 198.51.100.1, Last usable host 198.51.100.254, Total addresses 256, Usable hosts 254. The two addresses missing between 198.51.100.0 and 198.51.100.255 are the network address and the broadcast address, which is why a firewall object or an ACL usually wants the whole block and a DHCP pool wants the usable pair. The reverse direction works as well: the input accepts 192.168.0.0 - 192.168.1.255 and answers 192.168.0.0/23, on the condition that the range is exactly one aligned block — a ragged range such as 192.168.0.1 - 192.168.1.200 is refused outright. The error names the smallest block that would cover it — 192.168.0.0/23, which adds 56 addresses you did not ask for — and returns nothing, because silently widening a range is how an ACL ends up open to a whole /23.

Small prefixes follow the interface rules rather than the minus-two rule, and that is measured rather than asserted: 192.168.1.1/31 reports 2 usable hosts (RFC 3021 point-to-point) and 192.168.1.1/32 reports 1. For IPv6 the same rows stay exact — 2001:db8::/32 reports 79,228,162,514,264,337,593,543,950,336 addresses — and the broadcast row is left blank because IPv6 has no broadcast address.

Correctness: checked against a reference implementation

The interesting claim about a calculator is not speed. It is whether the answer is right — and for CIDR maths there is an honest way to demonstrate that: compare against something authoritative.

Every result this page produces is checked against Python's standard-library ipaddress module, the same code that ships inside CPython and the reference most network tooling is regression-tested against. The test vectors are generated from it, not hand-written by someone who thought they knew the answers.

  • 356 valid inputs, each compared field by field across the same 16 fields the page renders — cidr, version, network address, netmask, wildcard, broadcast, prefix length, total addresses, usable hosts, first host, last host, and the five IPv4 class flags private / loopback / link-local / multicast / reserved. That is 5,696 field comparisons, all equal. The three extra flags the panel shows — CGNAT, documentation, benchmarking — are this site's own prefix tables, not cross-checked against CPython, so treat them as ours rather than as the reference answer. IPv6 class flags are reported as unknown instead of guessed.
  • 15 malformed inputs that CPython also rejects — this page must reject every one, and say what is wrong rather than echoing "invalid".
  • 20 capability checks for collapse, split and containment, including the case that catches most implementations: /25s pasted in pairs that chain-merge upward. The vectors do 768 of them into 3 blocks; the bench does 10,000 into 5..

Fifty-six assertion groups in total, in a page that ships with the site (/test/). There is no CI behind it: the harness is re-run by hand before each publish, which is the honest version of that sentence. Two real bugs were caught that way before this paragraph was written: an IPv6 formatter that emitted its groups in reverse order, and a mask validator that compared a BigInt against a Number with !==, which made every dotted netmask look invalid. Neither is visible by eye.

Where a competitor is confidently wrong, it is usually one of three things: applying n − 2 to a /31 or /32, reading a wildcard mask as a netmask, or merging two adjacent blocks that are not actually aligned. All three are covered by the vectors above.

Why usable hosts are total minus two

Two addresses in every block are spoken for: the network address (how the block is named in routing) and the broadcast address (which every host on the segment hears). So a /24 is 256 addresses but 254 hosts, and a /27 is 32 but 30. It is not padding and not a convention you can skip — configure a DHCP pool that includes the network address and you have taken someone's host.

Two sizes break the rule, and a calculator that does not know them is a source of real outages:

  • /31 — two addresses, two usable hosts, per RFC 3021. Point-to-point links use exactly this so neither address is wasted. Subtracting two would report zero hosts for a working link.
  • /32 — one address, one usable host. There is no separate network or broadcast to remove; this is how you refer to a single host, and it is the right mask for loopbacks and host routes.

This page reports 2 and 1 respectively because the test vectors include both and CPython agrees. For IPv6 it does not apply minus-two at all: there is no broadcast address, so only the subnet-router anycast address (the first) is reserved and the last address of the block is a usable host — and a /127 or /128 reserves nothing, which is CPython's rule. The vectors carry all three IPv6 cases separately — 2001:db8::/126 gives ::1 to ::3 and 3 hosts, /127 gives both ends and 2 hosts, /128 gives 1. Prefixes too large to materialise reuse the same rule, which the generator checks against list(net.hosts()) on 20 materialisable prefixes (/24-/32 and /118-/128) before applying it to the rest.

CIDR, netmask, wildcard — three spellings, one meaning

These all describe the same block:

10.0.0.0/8
10.0.0.0 255.0.0.0        # dotted netmask
10.0.0.0 0.255.255.255    # wildcard / hostmask, Cisco ACL form
10.0.0.0 - 10.255.255.255 # inclusive range

The input box accepts all four, and it will not silently reinterpret the third: 255.255.0.255 is neither a valid netmask (ones must form one run at the top) nor a valid wildcard (ones must form one run at the bottom), so it is rejected with that explanation rather than rounded to something plausible. A mask copied from the wrong column is worth an error message, not a guess.

One behaviour to know about: paste 192.168.1.37/24 and you get 192.168.1.0/24, because host bits are not part of a network identifier. The page says so and shows the address you came from, instead of pretending you typed something else.

Collapsing a list, and why alignment matters

Two blocks merge into their parent only when all three hold: same prefix length, numerically adjacent, and the left one starts on an even multiple of the parent's size. The third condition is the one people miss.

10.0.0.0/25 + 10.0.0.128/25  →  10.0.0.0/24   ✓ adjacent and aligned
10.0.0.128/25 + 10.0.1.0/25  →  no merge       ✗ adjacent, but not a parent pair

That second case is the trap. 10.0.0.128/25 and 10.0.1.0/25 sit right next to each other and together span 256 addresses, but they are not a /24, so a tool that prints 10.0.0.128/23 has produced an invalid network — one that ip address add, a router, or a cloud security group will reject. Try it in the collapse tab and you get two rows back.

Removing blocks already covered by a larger one is the other half: put 10.0.0.0/8 next to 10.1.2.0/24 and the /24 disappears, which is usually the point — fewer rules, same permission set.

What this page deliberately does not do

  • No whois, no geolocation, no reverse DNS. Those need a server, and a server means your ranges leave your machine. Everything here is derived arithmetically from what you typed.
  • No IPv6 range classification. The arithmetic is exact for IPv6 — addresses, masks, ranges and counts up to 2128, which is why the engine uses BigInt rather than JS numbers. But the IPv6 private/reserved registries are long, and a partial copy produces confident nonsense, so the flags are omitted for IPv6 instead of guessed.
  • No classful columns. There is no "Class A/B/C" output. That scheme was retired by CIDR in 1993, and showing it gets it copied into configs that will reject it.
  • No claim about what you may route. Whether a block is yours to announce is between you and your RIR.

Frequently asked questions

Does my IP data get uploaded?

No. Parsing and arithmetic happen in the same tab; there is no request in the code path that parses your input.

Why does a /31 show 2 usable hosts instead of 0?

Because RFC 3021 reserves /31 for point-to-point links, where both addresses are usable — that is the entire reason the size exists. Applying the usual minus-two would report zero hosts for a working link, so this page follows the standard. A /32 gets one host for a comparable reason.

Can I enter a wildcard mask instead of a netmask?

Yes. 10.0.0.0 0.255.255.255 is accepted alongside the dotted-netmask and /8 forms. If what you give is neither a valid netmask nor a valid wildcard it is rejected with an explanation, not assumed to be one of them.

Why did my address change when I typed host bits?

It should have. 192.168.1.37/24 and 192.168.1.0/24 name the same network, and a network identifier never carries host bits. The page shows you both so nothing changed silently — echoing your typo back at you would hide the useful half of the answer.

Can it merge a list of CIDRs?

Yes — the collapse tab. Paste one block per line (or comma-separated) and it returns the minimal equivalent set, dropping anything already inside a larger block. Measured: 50,000 entries in 187.7 ms. It is checked against Python's collapse_addresses on 9 cases (20 capability checks in total, the rest being split and containment), including the alignment trap.

Does it handle IPv6?

For arithmetic, yes — including counts up to 2^128, which a plain JavaScript number cannot hold. For the private/reserved flags, no: the IPv6 registries are long enough that half-copying them would be worse than silence, so those fields are omitted rather than approximated.

Is 100.64.0.0/10 private?

It is the CGNAT range from RFC 6598 — shared among one carrier's customers, not globally routable, and not RFC 1918. CPython's is_private does not count it as private, so this page does not either; it reports a separate CGNAT flag instead, because "is this my carrier's NAT space" is the question people actually have.

Why is there no Class A/B/C column?

Classful addressing was superseded by CIDR in 1993. A /22 is "Class C" by first octet and a 1,024-address block in fact; the label answers no question the prefix does not answer better.
